# [Fat protocols aren't new: What blockchain can learn from p2p file sharing](https://medium.com/@jbackus/fat-protocols-arent-new-42d2c538db41)
### By John Backus
### Posted May 29, 2018

![](/assets/images/2018/m5/fat-protocols-arent-new-what-blockchain-can-learn-from-p2p-file-sharing1.png)

Starting in 1999, we saw an explosion of p2p file sharing technology. We had Gnutella (the protocol behind Limewire), FastTrack (Kazaa), eDonkey, and BitTorrent. **Limewire, Kazaa, and eDonkey all died, but the protocols they helped create lived on!**

People have speculated on what a future with [fat protocols](http://www.usv.com/blog/fat-protocols) will look like. File sharing protocols aren’t exactly the same, but they have a lot of similarities we can learn from.

Looking at the p2p ecosystem, a few things are clear:

* **Fat protocol ecosystems have way more variety and experimentation** when network effects don’t stop people from creating new clients
* **Protocols live on** and evolve regardless of whether the original creators are working on them or not
* The **application layer seems to capture little value for the protocol creator**,****but third party competition to build on top of the protocol may be a powerful force for finding product/market fit
* While people weren’t able to figure out how to integrate a token into p2p file sharing technologies back in the day, **it does seem like a properly calibrated token marketplace would have solved a lot of problems** and accelerated p2p’s breakneck adoption even more.

What file sharing application did you use before BitTorrent? Was it LimeWire, BearShare, Shareaza, giFT, Morpheus, Phex, or Acquisition? All of those were separate applications made by different teams that all connected to [Gnutella network](https://en.wikipedia.org/wiki/Gnutella#Software)! There was also FrostWire, LimeWire Pirate Edition, and WireShare which were forks of Limewire’s client.

I’m not going to do the same song and dance here listing a dozen clients for FastTrack and eDonkey, but [I could](https://en.wikipedia.org/wiki/Comparison_of_file-sharing_applications). Every protocol had tons of clients. In fact, Limewire wasn’t the creator of the Gnutella protocol, their app was just really popular because they added a lot of features.

##### Features

People didn’t all just build near identical clients of course. Different companies competed to build clients to the Gnutella protocol that served different needs. [BearShare](http://www.bearshare.com:80/screens.htm) seemed to focus on building a good client. It had a straightforward search, a “theater” to preview movies and music while they downloaded, and plenty of other features like a place to chat with other users.

![](/assets/images/2018/m5/fat-protocols-arent-new-what-blockchain-can-learn-from-p2p-file-sharing2.png)

BearShare provided a full featured experience

##### Quality

The eDonkey company developed their own network (“eDonkey2000 Network”) and a corresponding client. Even though they developed the protocol, they had to compete with a very popular open source client called [eMule](https://www.emule-project.net/home/perl/general.cgi?l=1) which many viewed as having a better user interface!

![](/assets/images/2018/m5/fat-protocols-arent-new-what-blockchain-can-learn-from-p2p-file-sharing3.png)

Which would you rather use?

##### Generalization

Some people tried to improving the user experience via better interfaces. Others tried to provide access to as much content as possible by creating clients that used multiple networks.

[Shareaza](https://en.wikipedia.org/wiki/Shareaza) became popular by supporting every file sharing protocol under the sun:

> Shareaza … supports the Gnutella, Gnutella2, eDonkey, BitTorrent, FTP, HTTP and HTTPS network protocols and handles magnet links, ed2k links, and the now deprecated gnutella and Piolet links

![](/assets/images/2018/m5/fat-protocols-arent-new-what-blockchain-can-learn-from-p2p-file-sharing4.png)

*Shareaza searcheseverything*

##### Abstraction

[The giFT project](https://en.wikipedia.org/wiki/GiFT) was similar to Shareaza in trying to implement every protocol, but it aimed to be a file sharing backend that others could build user interfaces for:

![](/assets/images/2018/m5/fat-protocols-arent-new-what-blockchain-can-learn-from-p2p-file-sharing5.png)

Two totally different frontends (GiFTcurs and Apollon) using giFT on the backend

giFT supported most protocols and was compatible with Windows, Linux, and Mac.
